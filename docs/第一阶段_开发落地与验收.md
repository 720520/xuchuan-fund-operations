## 数据与计算口径

1. 每条净值绑定管理人、产品、份额类别、估值日期、来源与收到时间。
2. 同产品不同份额分别存储；有效版本键为“份额 + 估值日期”。
3. 反账确认只切换有效指针。例如 8 月 31 日收到 8 月 28 日反账材料：估值日仍为 8 月 28 日、收到日期显示 8 月 31 日、状态“反账后”；原始 8 月 28 日记录不修改。
4. 当前曲线的“净值变化”为相对首条有效单位净值的变化；“净值回撤”为相对历史单位净值高点的回撤。两者**不是分红再投资总回报，也不是投资者收益**。
5. 附件明确披露的现金、仓位、收益率、回撤保留在解析字段中。完整持仓明细及披露口径尚未验证，不做猜测。
6. 资产净值展示原值。尚未确定托管按产品或按份额披露的规模口径，因此没有强行求和的集团总规模。
7. “今日写入 / 确认事件”按北京时间统计；“应收 / 收到 / 有效确认”按操作员选择的估值日期统计，两者不是同一个计数。
8. 原件收到、解析完成、数据校验和有效确认是不同状态；一个状态完成不等于其他异常也完成。

## 已进行的验证

- 后端业务回归：账号、CSRF 来源、登录限流、按牌照读写、产品范围、下载权、精度、重复解析、未识别产品建档后重解析、人工补齐、缺件与校验独立、反账及旧记录保护。
- PostgreSQL 并发测试：两个牌照成员同时处理同一异常仅一方成功；同时收到同份额同日不同净值时只有一个有效版本并形成冲突。
- 原件与审计表的更新 / 删除拦截、原始 EML 字节留存、UIDVALIDITY 改变后的相同邮件去重。
- IMAP 仿真验证只读选择与 `BODY.PEEK[]`，没有更改已读或删除邮件的调用。
- 前端 TypeScript 检查与生产构建；已修复初始 Vite 安全公告命中。
- 前后端公开依赖安全审计均未报告已知漏洞（本次扫描时点，不构成永久安全保证）。
- 本机页面联调使用独立测试账号与 `runtime/ui-qa-*` 临时数据，绝不作为正式基金数据。

最终验证记录：

- PostgreSQL 后端回归 **24 / 24 通过**，包含并发领取、并发净值、邮件单条失败后继续处理、跨牌照资料边界与管理员交接。
- 前端十进制格式测试 **3 / 3 通过**，覆盖大额数字精度、净值舍入与空值区分。
- TypeScript + Vite 生产构建通过；Ruff（F、E9）静态检查通过。
- PostgreSQL 首次迁移及 Alembic 结构一致性检查通过；SQLite 重复执行迁移及证据触发器检查通过。
- 实际浏览器走通：登录、创建产品和 A / B 份额、补录净值、同日第二值产生冲突、领取、反账原因必填、新值生效、旧记录保留。视觉检查已完成。
- 保留一个仅含构造数据的本机联调服务 `http://127.0.0.1:18000`；正式运行须另行初始化自己的数据库和账号。
- 已停止隔离 PostgreSQL 测试容器；页面联调使用独立测试 SQLite 数据库。
