# 开发说明

更新：2026-09-09。保留必要实现约束，替代重复的总体架构、前后端规范和开发实施手册。产品规则见[产品范围](产品范围.md)，工作顺序见[开发阶段](开发阶段.md)。

## 现有结构

- `frontend/`：React + TypeScript + Vite，正式页面与 API；`preview/` 仅历史演示源码。
- `backend/app/main.py`：API；`services.py`：业务处理；`models.py`：数据模型。
- `mail_sync.py`：只读邮件同步；`mail_classification.py`：分类、待办和解析分流；`worker.py`：收件/分类/解析调度；`custodian_parsers.py`：托管适配器。
- `security.py`、`mailbox_security.py`、`immutability.py`：权限、凭据和证据保护。
- `backend/migrations/`：数据库迁移；`backend/tests/`：业务、并发、迁移及启动器测试。
- 启动、邮箱配置及部署命令统一维护在[项目 README](../README.md)，不在此复制。

继续使用现有模块化单体。只在涉及真实需求时拆分大文件；不为长期对象、路由库或消息中间件重写已验证业务。

## 本轮实现与启用（2026-09-08）

新增 `trading_calendar.py` 和 `receipts.py`，分别维护离线交易日历和应收检查；仍使用原有单体、后台进程和数据库，不新增服务。迁移 `0005` 增加牌照应收配置和按份额/估值日唯一的应收记录；原始材料、净值版本和审计表保护不变。

启动前按原部署流程执行 Alembic 到 `head` 并重建前端，然后重启 API 与 Worker。本地“一键启动”会执行迁移及按变化重建；本轮未对业务数据库执行迁移。

管理员进入“组织与权限 → 净值自动应收”，核对日历、起始日和跟进时间后启用。首次不自动回溯启用前缺件，默认跟进时间 09:00 可调整；停止后重新启用不补造暂停期间的应收。Worker 约每分钟检查一次，具体延迟受同步/解析任务运行时间影响，最近检查及失败原因在页面可见。

- 日频截止固定 15:00，恰好 15:00 不判迟到，超过后判迟到；旧日频保存值不再支配自动截止。周频保留独立截止；按配置星期遇休市取此前交易日，下一交易日应收。
- 每项应收保存当时的截止、跟进时间和日历版本；后续设置不改写已有应收。停机后从上次调度日期补查，使用当时可获得的产品配置，不重建完整历史配置；手动历史检查同样按当前配置。
- 使用上交所 2025–2026 年日历，并展示国务院节假日及调休；不把调休上班日当证券交易日。首页右栏提供紧凑月历。Worker 每 30 天拉取并核验官方页面，页面内容变化时提示人工复核，不静默改变业务截止日期。跨年未覆盖时停止相应自动检查并显示错误，不能自动推测，也不覆盖港股或其他市场日历。产品开放日联动暂不提供。
- 邮件使用已保存的邮箱到达时间（IMAP INTERNALDATE，缺失时使用同步时间）；上传/人工录入使用各自接收时间。无法匹配产品、份额、日期的邮件不能解除缺件。
- 收到可识别净值后解除缺件，校验或冲突另行保留。原件已到但无法解析时，有原件权限的成员可在缺件详情关联附件并填写依据，解除缺件但不确认净值。
- “记录已在托管平台补发”只记本人操作和原因，保留待办；版本校验防止并发覆盖。产品清算、归档或停收取消对应应收，原件和历史仍保留。

同牌照多邮箱仍可使用。迁移 `0006` 新增邮件分类、产品关联和邮件待办；系统先分类，只有净值/估值邮件的受支持附件进入解析。明确风险、业务动作和安全提醒形成待办，普通通知形成接收记录，未知内容进入待分类。邮件摘要会去掉 HTML 中的样式、脚本等不可见内容并限制为两行，表格在窄屏隐藏次要列。历史邮件由 Worker 分批补分类；此前误排队且尚未处理的非净值附件标记为“已跳过”，保留任务记录和原件。解析任务查询再次校验邮件分类，未分类邮件不会先行解析。

“全部业务文件夹”自动排除 IMAP 标记或常见名称识别出的已发送、草稿、垃圾邮件和已删除目录；其他可读取目录仍会同步。此范围用于日常自动处理，不删除或移动邮箱内邮件。

## 资料整理的实现边界（首批已落地）

“上传与解析”已调整为“资料中心”。页面提供资料总览、待整理/已关联/处理中视图，以及产品、类别、来源和关键词筛选；产品台账可直接进入该产品的资料视图。邮件正文原件不混入业务资料列表，可识别的既有净值附件沿用当前解析状态，其余历史资料显示为待整理。上传后可人工确认资料标题、类别、业务日期或期间、说明及一个或多个关联产品。

迁移 `0007` 新增独立的资料整理记录及资料—产品关联，不修改 `Document` 的不可变字段。保存使用版本号防止旧页面覆盖新结果，并记录修改前后内容、账号和时间。历史 `Document.product_id` 与来源只读保留：未整理资料以原关联兼容展示，首次确认后以整理关联为准。确认“净值与估值”会创建或恢复净值解析任务；确认其他类别会停止尚无业务结果的解析任务。已有净值记录不会因重新分类而删除或失效。

批量归类、服务端分页、版本分组及材料导出仍待实现。后续批量动作须逐条返回成功、失败或冲突，搜索结果、批量操作和下载继续在服务端校验。

## 修改时必须保持的边界

1. 管理人和对象归属由服务端校验；查看不自动带来写入、原件或下载授权。后台任务也携带管理人范围。
2. 原始邮件/附件、候选净值、历史版本和审计不能被新值覆盖。候选追加、有效指针切换必须一致；多份额和估值日不能混淆。
3. 净值金额使用十进制；不静默舍入、不猜缺失字段；收到时间与估值时间分开。
4. 异常提交校验版本，并发冲突不可覆盖他人结论；业务结果和关键审计须保持一致。
5. 邮箱只读；连接后只向业务代码开放列目录、只读选目录、搜索以及 `RFC822.SIZE`、`INTERNALDATE`、`BODY.PEEK[]` 读取，不开放删除、移动、复制、追加、标记、目录修改或发送能力。同步/解析可去重和重试；凭据不进入日志或 API 明文响应；格式未知进入人工处理。
6. 迁移兼容旧数据，先在隔离库验证；禁止测试连接业务数据库，禁止用真实资料填演示页面。
7. 只对实际改动做相关测试；涉及生效/权限/任务时跑业务回归，涉及并发时使用 PostgreSQL，不能用 SQLite 替代。
8. 正式发布前验证备份恢复、权限、附件隔离及目标环境。数据库管理员级防篡改另行落实，不夸大当前触发器能力。

## 本轮复现命令

从项目根目录运行。数据库 URL 为仓库专用临时测试库，不是业务凭据。

```bash
env -u TEST_DATABASE_URL timeout 180 .venv/bin/python -m pytest backend/tests -ra
docker compose -f compose.test.yaml up -d --wait
env TEST_DATABASE_URL=postgresql+psycopg://qa:qa-isolated-local-only@127.0.0.1:55432/xuchuan_test timeout 180 .venv/bin/python -m pytest backend/tests -ra
docker compose -f compose.test.yaml stop
npm --prefix frontend test
npm --prefix frontend run build
```

首次启动器端到端测试需要已有前端构建及 `runtime/launcher-build.json`，具体前置条件以 `test_launcher.py` 为准。专用测试库中的每个 schema 由测试生成并清理；部分测试始终用临时 SQLite，本轮 PostgreSQL 运行并非每个测试都切换数据库。

隔离页面验收：

```bash
env PYTHONPATH=backend .venv/bin/python backend/tests/serve_qa.py --port 18007
```

该脚本生成独立 `runtime/ui-qa-*` 测试目录并禁止真实邮件同步。仅使用其测试账号，验收结束停止该服务。模板新增与只读回放见[托管适配器说明](托管解析适配器开发说明.md)。
