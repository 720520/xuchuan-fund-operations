# 资料中心双向布局调整方案

更新日期：2026-09-11
范围：资料中心前端信息架构与交互预览，不改变现有归档、权限和下载接口。

## 1. 调整目标

现有“资料 / 投资者”页签把资料和主体分开了，能够分别查询，但不能直接回答以下日常问题：

- 这个产品有哪些投资者，各自有哪些资料？
- 这个投资者投了哪些产品，在每个产品下有哪些资料？
- 一份材料同时关联了哪个产品和投资者，关系是否已经核对？
- 当前看到的是主体全部资料，还是某一对“产品—投资者”的共同资料？

新页面使用一个双向关系工作台。用户可在“按产品”和“按投资者”两个方向间切换，所选主体、关联对象和资料范围始终显示在同一屏内。

## 2. 参考依据

- [Material Design 的 list-detail 布局](https://m3.material.io/foundations/layout/canonical-examples/overview)适合“左侧选择、右侧查看上下文”的连续工作，减少在列表页和详情页之间跳转。
- [Ant Design 数据展示规范](https://ant.design/docs/spec/data-display/)建议按信息的重要性、频率和关联组织内容；结构化资料继续使用表格，便于比较、筛选和分页。
- [Atlassian Dynamic Table](https://atlassian.design/components/dynamic-table)把排序、分页和行级操作放在数据表本身，适合资料量逐步增长后的高频处理。
- [Fluent 2 Layout](https://fluent2.microsoft.design/layout)强调用网格建立稳定层级，并根据窗口宽度收缩辅助区域。

这些规范共同支持“主体列表 + 关系上下文 + 资料表”的布局。视觉继续沿用当前项目的米白、暖棕和灰绿色，不引入另一套设计语言。

## 3. 页面结构

```text
┌─ 资料中心 ─────────────────────────────────────── 上传资料 ┐
│ 关系工作台   全部资料   待整理                                      │
│ [按产品] [按投资者]        搜索主体…       状态/类别/来源筛选          │
├──────────────┬──────────────────────────────────────────────┤
│ 主体列表      │ 当前主体摘要                                        │
│              │ 吉余示例一号  · 12 位投资者 · 36 份资料 · 3 待核对     │
│ ● 产品 A      ├──────────────────────────────────────────────┤
│   产品 B      │ 关联投资者                                          │
│   产品 C      │ [投资者甲  6份] [投资者乙 4份] [投资者丙 2份]          │
│              ├──────────────────────────────────────────────┤
│              │ [产品A] → [投资者甲] → 共同资料 6                       │
│              │ 类别 | 资料标题 | 业务日期 | 来源 | 状态 | 操作          │
└──────────────┴──────────────────────────────────────────────┘
```

### 顶部视图

- **关系工作台**：默认入口，用于产品和投资者双向查找。
- **全部资料**：保留现有资料总表和全部高级筛选。
- **待整理**：只显示未分类、未关联或待核对资料。
- **上传资料**：保留现有入口。

首页不再使用“资料 / 投资者”作为互相隔离的模块页签。投资者建档和编辑入口放在关系工作台中，并保留权限控制。

### 左侧主体栏

- “按产品”时显示产品列表；“按投资者”时显示投资者列表。
- 每行只展示名称、代码或类型，以及关联数、资料数、待核对数。
- 支持名称搜索和“仅看有待办”筛选。
- 左栏固定宽度约 280px；窗口较窄时变为可展开的选择面板。

### 主体摘要

显示当前产品或投资者的基本信息，并给出三个紧凑指标：关联主体数、资料数、待核对数。这里只展示判断当前工作量所需的信息，详细字段在主体详情抽屉中查看。

### 关系区

- 选中产品后，显示它关联的投资者。
- 选中投资者后，显示其关联产品。
- 关系卡显示关系状态、资料数量和待核对数量。
- 点击关系卡后，资料表自动收窄为两者的共同资料。
- 再次点击或点“清除关联”回到主体全部资料。

### 资料范围条

资料表上方始终显示当前查询范围，例如：

`吉余示例一号 → 示例投资者甲 → 共同资料 6`

这能防止用户在处理资料时忘记当前筛选条件。关系范围、类别、状态和搜索词分别显示为可移除条件。

### 资料表

建议列顺序：

| 列 | 展示内容 |
|---|---|
| 类别 | 一级类别，使用低饱和色标签 |
| 资料 | 整理标题；下一行显示原文件名 |
| 关联 | 当前方向下的另一侧主体 |
| 业务日期 | 资料自身业务日期；无值显示“待补充” |
| 来源 | 邮件、人工上传、历史导入 |
| 状态 | 已整理、待整理、待核对、处理中 |
| 操作 | 查看、整理；下载放入“更多”菜单 |

不把完整产品列表、投资者列表和长文件名挤在同一行。点击资料行打开右侧详情抽屉，展示原件、来源邮件、全部关联、整理历史和下载入口。

## 4. 双向操作流程

### 从产品查投资者资料

```mermaid
flowchart LR
    A[切换到按产品] --> B[选择产品]
    B --> C[显示关联投资者和产品全部资料]
    C --> D[选择一个投资者]
    D --> E[只显示两者共同资料]
    E --> F[打开资料详情或进行整理]
```

### 从投资者查产品资料

```mermaid
flowchart LR
    A[切换到按投资者] --> B[选择投资者]
    B --> C[显示所投产品和投资者全部资料]
    C --> D[选择一个产品]
    D --> E[只显示两者共同资料]
    E --> F[打开资料详情或进行整理]
```

两个方向共享同一组数据关系。切换方向不创建副本，也不改变原件状态。

## 5. 响应式规则

| 内容宽度 | 布局 |
|---|---|
| 1280px 以上 | 280px 主体栏 + 自适应主区；资料详情使用右侧抽屉 |
| 900–1279px | 主体栏缩为 240px；关系卡横向滚动；隐藏低频表格列 |
| 900px 以下 | 主体栏变成顶部选择器；资料表使用卡片行；详情全屏打开 |

关系卡允许自身横向滚动，但整个页面不产生横向滚动。

## 6. 与现有功能的衔接

可以直接复用的能力：

- 资料服务端分页、搜索、类别、来源、敏感级别、产品和投资者筛选。
- 投资者建档、编辑、产品多选关联和资料数量。
- 资料整理、原件下载、来源邮件、权限校验和审计。

正式落地时建议补两个聚合接口，避免前端用当前一页资料计算错误数量：

1. `GET /api/managers/{id}/material-entities?perspective=product|investor&q=...`
   返回主体列表，以及关联主体数、资料数和待核对数。
2. `GET /api/managers/{id}/material-relations?product_id=...` 或 `investor_id=...`
   返回另一侧主体、关系状态、共同资料数和待核对数。

资料表继续使用现有分页接口；选择产品和投资者时同时传入两个筛选参数，即可得到共同资料。

## 7. 建议实施顺序

1. 先把资料中心改为关系工作台壳层，复用现有接口和页面操作。
2. 增加主体及关系聚合接口，让统计不受资料分页影响。
3. 将资料详情改为右侧抽屉，补齐全部关联和整理历史。
4. 加入关系状态的人工确认，以及疑似重复投资者提示。
5. 最后增加批量整理、账户和报送批次关系。

## 8. 验收标准

- 用户不超过三次点击即可从一个产品定位到某投资者的共同资料，反向同样成立。
- 页面任何时候都能明确看出当前产品、投资者和资料筛选范围。
- 页面主体区域不产生横向滚动。
- 资料数量来自服务端聚合，不受当前分页影响。
- 资料原件、敏感权限、下载审计和邮件只读约束保持不变。
- 产品与投资者只建立关系，不在资料中心直接修改托管份额。
