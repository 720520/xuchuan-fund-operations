# 图标设计师

一个用于设计、生成和管理数字产品图标集的综合技能。本技能将引导您完成完整的图标工作流程：分析项目图标需求、生成AI图像提示词、处理图标资源以及实施图标替换。

## 何时使用此技能

在以下情况下使用此技能：
- 用户需要为APP、小程序或网站创建或更新图标
- 用户想要分析项目当前使用了哪些图标
- 用户需要生成用于图标创建的AI图像提示词
- 用户有一张需要拆分为单独图标的精灵图或组合图片
- 用户想要在整个项目中用新图标替换现有图标
- 用户询问图标设计、风格一致性或图标系统相关的问题

## 核心工作流程

图标设计过程遵循以下阶段：

### 阶段 1：图标发现

在创建新图标之前，先了解项目当前需要哪些图标。

**扫描项目中的图标使用情况：**
1. 在代码中搜索图标文件引用（`.png`、`.svg`、`.jpg` 图标文件）
2. 查找图标组件使用情况（例如 `<Icon>`、`<FontAwesomeIcon>`、`<AntDesign>`）
3. 检查资源目录中现有的图标文件
4. 识别需要图标的UI元素（导航、操作、状态指示器）
5. 梳理需要哪些图标

**使用的工具：**
- 使用 `Grep` 查找图标文件引用：`\.png|\.svg|\.jpg.*icon|icon.*\.(png|svg|jpg)`
- 使用 `Glob` 查找图标资源：`**/icons/**`、`**/assets/**/*icon*`
- 阅读组件文件以了解图标使用模式

**输出：** 创建一个图标清单列表，显示：
- 图标名称/用途
- 当前文件位置（如果存在）
- 使用上下文（在哪里使用）
- 尺寸要求
- 格式（PNG、SVG等）

### 阶段 2：风格分析

确定图标集的视觉方向。

**如果用户提供了参考图片：**
1. 使用 `mcp__4_5v_mcp__analyze_image` 工具分析参考图
2. 提取风格属性：调色板、描边宽度、圆角半径、填充样式、视觉密度
3. 记录设计模式：轮廓 vs 填充、背景使用、阴影/深度

**如果没有提供参考图：**
1. 询问用户关于其产品的视觉识别
2. 根据项目类型确定合适的风格：
   - **现代APP**：扁平或渐变、圆角
   - **企业/工具类**：线性或填充图标、一致的描边宽度
   - **消费类APP**：活泼，可能是3D或插画风格
   - **小程序**：简洁、小尺寸下高度可识别

**需要记录的关键风格决策：**
- 填充样式（轮廓、填充、双色等）
- 圆角半径（锐角、略圆、全圆）
- 描边粗细（如果是轮廓：细、中、粗）
- 调色板（主色、辅色、强调色）
- 背景处理（无、圆形、圆角方形等）
- 视觉密度（极简、适中、详细）

### 阶段 3：提示词生成

为每个图标生成AI图像提示词，适用于Nano Banana Pro。

**提示词结构：**
每个提示词应包括：
1. **主题**：图标代表什么
2. **风格**：来自阶段2的设计风格
3. **技术规格**：尺寸、格式、透明度
4. **上下文**：使用上下文以确保适当性

**提示词模板：**
```
一个 [风格描述] 的 [主题] 图标，[具体风格属性]。
[关于构图、颜色等的额外细节]
技术规格：[尺寸]，透明背景，[格式]，适用于 [上下文]。
```

**提示词示例：**

*轮廓图标，现代APP风格：*
```
一个干净、现代的日历带勾选标记的轮廓图标。
极简设计，2px一致的描边宽度，略圆的角落（4px半径），
无填充。在透明背景上渲染。颜色：#3B82F6（蓝色）。
风格：类似于Linear或Feather图标的扁平UI设计。
尺寸：512x512px，高对比度，针对小尺寸优化（小至24x24px）。
```

*带渐变的填充图标：*
```
一个充满活力的购物车填充图标。
从#FF6B6B到#FF8E53的现代渐变，柔和的阴影带来微妙深度，
完全圆润的形状（12px圆角半径）。干净的轮廓，无内部细节。
在透明背景上渲染。风格：iOS风格的填充图标，充满活力的渐变。
尺寸：1024x1024px，边缘清晰，适用于电商APP。
```

**提示词生成最佳实践：**
- 明确风格属性（描边宽度、圆角半径、颜色）
- 包括技术要求（尺寸、透明度）
- 提及类似的图标集或设计系统作为参考
- 指定查看上下文（移动APP、网站等）
- 包括尺寸优化说明（例如"在32x32px时必须保持清晰"）

**输出：** 创建一个提示词文件（`icon-prompts.md`），每个图标一个提示词。


### 阶段 4：图标替换

在整个项目中用新图标替换现有图标。

**替换策略：**
1. **映射旧图标到新图标：** 创建映射文件
2. **处理不同场景：**
   - 直接文件替换：相同路径，新文件
   - 组件更新：更新图标组件导入/属性
   - 多种尺寸：如需要生成变体
3. **验证替换：** 检查新图标是否正确渲染

**实施：**
1. 使用 `Edit` 或 `Write` 更新图像文件
2. 如果图标名称更改，更新组件导入/使用
3. 搜索硬编码的图标引用并更新
4. 如果可能，测试渲染（为Web项目启动开发服务器）

**注意事项：**
- 保持原始纵横比
- 与现有图标保持一致的尺寸
- 如适用，处理亮色/暗色模式变体
- 一致地更新任何图标命名约定

## 输出格式

**图标清单：** 保存为 `icon-inventory.md`，包含以下结构：
```markdown
# 图标清单

## 摘要
- 总图标数：[数量]
- 需要新建：[数量]
- 需要替换现有：[数量]

## 图标
| 名称 | 用途 | 当前路径 | 尺寸 | 格式 | 状态 |
|------|---------|--------------|------|--------|--------|
| calendar-check | 完成事件的日历带勾选标记 | assets/icons/calendar.png | 24x24 | PNG | 替换 |
| user-profile | 用户头像占位符 | 无 | 48x48 | SVG | 新建 |
...
```

**提示词文件：** 保存为 `icon-prompts.md`，每个图标类别都有单独的部分。

**图标映射：** 保存为 `icon-mapping.json`：
```json
{
  "old_icon_name.png": "new_icon_name.png",
  "component_path": "updated_component_path"
}
```

## 成功技巧

1. **从发现开始**：在了解需要哪些图标之前，不要生成提示词
2. **首先确立风格**：所有提示词应遵循相同的风格指南
3. **提示词要具体**：模糊的提示词会导致不一致的结果
4. **在小尺寸下测试**：图标在24x24px或更小时必须保持可识别
5. **保持一致性**：描边宽度、圆角半径和视觉重量应在整套图标中保持一致
6. **有意义的命名**：图标文件名应描述其用途，而不是其外观
7. **保留上下文**：在设计时考虑每个图标将在哪里使用

## 常见场景

**"我需要为我的APP制作图标"**
→ 运行阶段1发现需求，然后运行阶段2确立风格

**"这是一张参考图，按照这个风格制作提示词"**
→ 运行阶段2分析参考图，然后运行阶段3生成提示词

**"把这张图片拆分成单独的图标"**
→ 运行阶段4进行图像处理

**"用这些新图标替换所有旧图标"**
→ 运行阶段5更新项目

**"全部都要做 - 我需要一套完整的图标集"**
→ 按顺序运行所有阶段

## 错误处理

如果图像处理失败：
- 检查精灵图网格尺寸是否正确
- 验证图像格式是否受支持（PNG、JPG等）
- 确保输出目录具有写入权限

如果图标替换破坏了UI：
- 验证文件路径完全匹配
- 检查新图标尺寸是否与旧图标相似
- 查找可能需要清除的缓存资源
- 如果可能，在实际运行环境中测试
